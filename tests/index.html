How to read this page

Two datasets, and why they are not merged

The development set (data/evaluation-data.js, 48 cases) was written alongside the classifier. Cases written while you are building the thing they test end up shaped by it, so accuracy on this set is a regression check: it tells you whether a change broke something that used to work. It is not a generalisation estimate and it should not be read as one.

The held-out set (data/evaluation-holdout.js, 48 cases) was written after the classifier and the lexicon were finished, without consulting either, and has never been used to tune anything. The gap between the two numbers is the honest measure of how much the development set flatters the system. A held-out score meaningfully below the development score is the expected result, not a bug, and it is reported rather than smoothed over.

The rule that keeps this honest: when a held-out case fails, the response is to report it. Adding its wording to the lexicon would convert the held-out set into a second development set and destroy the only property that makes it worth having.

Confusion matrices

Rows are the label a reasonable reader assigned. Columns are what the system predicted. The outlined diagonal is where they agree. Reading along a row shows what a given signal gets mistaken for, which is more useful than a single accuracy number when deciding what to fix next.

Ablation

Runs the identical dataset twice, once with the rule engine alone and once blended with the on-device sentence embedding model, and reports the difference. This is the measurement that justifies shipping the model at all, and it is the reason the model is optional: if a metric does not move, the 23 MB download is not buying anything for that metric.

Notes and limitations

Blended evaluation needs the on-device model, roughly 25 MB from a public CDN. The rule-engine path needs no download and is what node tests/run-node.js --eval measures.

Both datasets were written by the project author. Author-written labels are a real methodological limitation: they establish that the system behaves as its designer intends, not that the designer's intent matches how other people read the same text. The blind labelling tool exists to close that gap, and reports Cohen's kappa against a second annotator who never sees the stored label.

96 labelled cases across ten signal classes is a small set. Per-class figures for classes with three or four supporting examples carry wide error bars and should not be quoted as precise.
